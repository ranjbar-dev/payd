# Dashboard UI review — 10 September 2026

This pass refines the existing OLED/amber design. Shared changes apply across the dashboard; page-specific edits address the problems found in forms, navigation, and list states. Backend code, API contracts, polling, monetary values, and mutation safeguards are unchanged.

## Improvements

- Responsive shell: desktop sidebar, native mobile navigation disclosure, persistent alarm counters, UTC clock, and return breadcrumbs for nested routes. Removed the nested main landmark.
- More readable secondary labels, consistent form controls, visible hover/focus states, and 44px mobile controls. Large filter groups collapse on mobile; payment lookup remains visible.
- Compact tables with sticky column headings and first-column identifiers, keyboard-accessible scrolling, per-column skeletons, and preserved table semantics. Nested links and copy buttons no longer trigger row navigation.
- Copy success is visible and announced; clipboard failures have feedback. Pagination now accurately says “First page.”
- Worklist completion is distinct from empty search results. Mobile orders and payments have explicit loading and empty states.
- Confirmation dialogs are centered, bounded to the viewport, and named for assistive technology. Payment details use a native modal dialog for focus containment and Escape handling.
- Login has clearer instructions and pending feedback. Upstream service failures are no longer described as invalid credentials.
- Missing records retain page context. Missing routes and unexpected dashboard errors use the application’s visual language and provide a route back to the overview.

## Validation

- `npm run lint`, `npm run build`, and `npm test` pass. The four guardrail tests cover numeric money coercion, at-most-once proxy mutations, and session validation.
- All 22 dashboard route shapes were navigated at 390, 768, and 1440px, with no document-level horizontal overflow in those checks. Tables retain their own scroll areas. Representative screenshots were inspected at desktop, tablet, and mobile sizes, plus the withdrawal compose layout at 1182px.
- Real pointer clicks tested navigation, row opening, copy, and dialog opening. Keyboard Enter opens an order row; Escape dismisses dialogs. Mobile filters expand, update the URL, show an empty result, clear, and restore the list. Mobile navigation closes after selecting a destination.
- The withdrawal wizard remains unavailable below 1024px. No fund-moving action, order mutation, or webhook delivery was submitted.
- The Impeccable mechanical detector returned no findings. No browser console errors were returned by the final system-tab inspection.

## Limits of verification

The configured port 8080 was occupied by an unrelated HTTP server. Validation used the existing Nile development configuration on temporary port 18080 and a process-only preview override; saved environment configuration was not changed. Existing local records were used, with no invented business records. Chain/price access was unavailable in the sandbox, so cached and degraded states were visible.

There were no local withdrawal records. Populated withdrawal detail, estimate, and successful submission states were reviewed in source but not exercised with a real transaction. The unexpected-error boundary was compiled and source-reviewed, not triggered by deliberately breaking the application. Route overflow checks do not assert that every possible data length or runtime state was visually exercised.
